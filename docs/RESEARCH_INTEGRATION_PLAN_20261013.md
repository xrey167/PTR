# Research integration plan — five work packages

*Recorded 2026-10-13. Baseline: `cbe93da6`, the head of `main` after PR #132. Each package is its own branch and draft pull request; this file is the shared record and each package updates only its own row.*

## Context

A read-only comparison of `PTR-Research` (Python) with PTR (Rust, 2026-10-13) found PTR stronger on contracts, security and durability (ledger, fenced leases, preregistration) and the research repository stronger on the learned and operational parts: learned pod addressing, a head for a stable pod identity, reflex and failover, ACL and time filters in search, training integrity checks, an executable layering check, an adaptive batcher, adapter promotion as ledger events and a safety contract for the self-improvement loop.

Decisions: all five priorities as a roadmap; training in `training/` (Python), inference in Rust. The research mechanics are carried over onto PTR types, not ported line by line. Learned scores stay advisory, abstention is a valid result, head changes go through the ledger, and every research claim becomes a preregistered experiment with a baseline and a kill criterion.

## Definition of done per package

Everything named in the package is implemented without widening scope; formatting, check, clippy with `-D warnings`, tests and rustdoc are green with the package's feature-gated tests; every changed crate has an updated `component.toml` and regenerated docs; tests follow `docs/TESTING.md` with a negative test per security rule; experiments and evaluations are registered and validate, with no `must-be-pinned` placeholder once an experiment leaves `planned`; the design document, ADR and catalogs are present; the branch is pushed and the draft pull request names the evidence and the open points.
