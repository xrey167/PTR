### Implemented now

- PtrRuntime::run_model_run_resumable(request_id, raw_text, infer) is the entry point for a ModelRun-producing (KV-reusing) backend: it ingests the request text, calls `infer` with the resulting SemanticContext, and builds the ResumableRun only through ingest_model_run (so Approximate taint is recorded and authorize_action refuses the action), emits RequestFinished for a finished run without control events, refuses a run that requests a Pod with RuntimeError::Model (this path does not resume Pods) and a run with neither Finished nor an action with ModelNoProgress. Used by ptr-server's ServerBackend::KvReusing; covered by ptr-server tests/kv_taint.rs
- ReferenceKvReuseBackend (src/kv_infer.rs), the first KvReusingBackend that really reuses KV: it owns an InMemoryPagedKvBackend, a KvPrefixCatalog over it and the R005 tiny Qwen2 reference stack (seeded random weights, PreRope keys, f32 CPU), looks up the longest live exact prefix of a SegmentedModelRequest, forks it through the witness-gated path, prefills only the remaining tokens one 16-token chunk at a time (publishing and inserting every completed prompt chunk boundary), decodes greedily up to a bounded max_new_tokens and returns a ModelRun whose KvReuseReport is always Exact (it never produces Approximate). A prompt that is entirely cached is refused as a hit and prefilled again, because the last prompt token's logits are not in a cache. Catalog capacity, a draining slot or a dead dependency are a graceful insert miss counted in the outcome (and the refused backend prefix is retired unless another entry holds it); they never change the output. Prompt length, generated length and catalog limits are bounded with typed ReferenceKvError values; principal and project enter the KvSalt and the page binding, so scopes never share an entry; invalidate_inputs and flush tombstone and retire entries. The same type implements plain InferenceBackend as the cold path (no lookup, no insert, no report). The run's taint is Exact and ingest_model_run accepts it. With ReferenceKvReuseBackend::with_rope_scaling and Qwen2RopeScaling::DynamicNtk each request fixes its RoPE regime once at admission from prompt_tokens + max_new_tokens, runs prefill and decode under it, derives its chain id (and page-binding manifest) under it and reports it in ReferenceKvOutcome::rope_regime, so requests in different regimes never share an entry: a request whose admission regime differs from a cached entry's misses and is recomputed (Exact, bitwise equal to its own cold run), and lengths up to the original maximum positions share one regime. Covered by tests/kv_infer.rs (cold versus warm 32-token shared prefix: hit_tokens == 32 and bitwise equal text, tokens and logits digest; principal, project and revision isolation; invalidation and flush; capacity; ingest)
- R007 WP1 probes on the reference KV backend: ReferenceKvReuseBackend::probe(scope, request, ReferenceKvProbeMode::{Cold, Warm, StaleDonor}) runs the one-shot path and also returns ReferenceKvProbe { outcome, prompt_logits (the full 256-entry next-token logits vector at the last prompt position, compared on f32 bit patterns via logit_bits), kv_state_digest }; KvSession::prompt_logits and KvSession::kv_state_digest give the same stepwise. kv_state_digest is SHA-256 over domain ptr.kv.reference-state.v1, prompt_tokens, layers, row_width (u64 little-endian), then per layer the K rows and V rows of positions 0..prompt_tokens as f32 bits little-endian, so it is independent of pages, chain ids and salts and equal for a cold run and a run that reused part of its rows. A span is modelled as a revocable Derived or Memory segment and forgotten by invalidate_inputs on its identity; no new primitive. StaleDonor is a negative control only: it looks up a donor request under an always-live oracle, cuts the forked rows to the last chunk boundary below the prompt and inserts nothing. ReferenceKvLimits::max_prompt_tokens can be raised per instance (default stays 256; the chain id and the tiny-model config digest do not depend on it). Covered by tests/kv_span_forget.rs; the full 4224-token case is an ignored release-only test (one cold prefill takes about a minute)
- KV-reuse P2a taint at the action boundary (src/kv_taint.rs): PtrRuntime::ingest_model_run takes a ptr_model_api::ModelRun, returns a ResumableRun whose new kv_taint field is the run's KvReuseTaint, and for an Approximate run records the run's single action by a revision- and generation-independent identity digest (target, operation, capability, input type, effect, payload; domain-separated from action_digest, so re-stamping a stale action to a newer revision or generation keeps the taint) in a bounded (MAX_LIVE_TAINT_SUBJECTS = 65,536 live subjects) persistent registry (see the next entry) that fails closed with KvTaintRegistryFull; authorize_action checks it first and refuses a recorded action with RuntimeError::ApproximateStateAtEffectBoundary { report_digest } (and check_execution_action refuses it too, so prepare_execution, prepare_execution_once and execute_prepared do not rely on authorize_action; also reached through the Pod ActionProposal admission paths), authorize_action_with_taint takes a caller-held taint, an Exact or no-report run behaves as before, a later Exact ingest of the same action does not clear the taint, and a run with several control events is refused before anything is recorded. ## Mission

Keep orchestration out of `ptrd` and out of individual domain crates. The runtime coordinates transitions while each component retains ownership of its semantics.

## Current boundary

The executable reference slice now wires configuration, semantic revisioning, a backend-neutral model call, semantic Pod resolution, Pure/Read Pod execution, verifier-gated observation promotion, action authorization, event emission, ledger materialization and durable FileLedger reopen/replay. The new scoped synchronous execution gateway binds opaque sessions and immutable ActionIR permits to host-registered verifiers/executors. Administrative session registration assumes the embedding host has authenticated the principal; it is not an HTTP authentication endpoint. See [P0.1 execution authority](../../docs/architecture/21-scoped-execution.md) for guarantees, counterexamples and the remaining durable/network gates. P0.2 now reconstructs the actual journaled semantic payloads, dependencies and revisions. The next persistence gate is record integrity and verified snapshot/checkpoint admission, not additional backend breadth.
