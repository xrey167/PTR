### Implemented now

- TCP and UDP executors refuse a request under a topic policy or on an MQTT link with EgressRefusalReason::TopicUnverifiable (code 6), because they send the payload unchanged and cannot tie a declared topic to the wire; check_publication is kept for an executor that reads the topic from its frame
- Topic policy is total: a policy that lists topics refuses a request that names none (EgressRefusalReason::TopicRequired); a refused topic is recorded as a digest prefix and length (redact_topic), a host or port refusal as a hashed host with its port (redact_endpoint, host:<16 hex>:<len>:<port>); PodLink and native validation use milliseconds since the epoch
- Egress enforcement (src/egress.rs): MQTT-style topic filters (+ and #, $-topics, bounded) checked against EgressPolicy.topics, EgressPolicy::check_endpoint / check_topic, ProtocolError::EgressRefused { target, reason } with a redacted target, NativeProtocolRequest.topic, and FrameRateLimiter, a bounded integer token bucket per Pod lease wired into the TCP and UDP executors
- Global workspace contract (src/workspace/, doc 37; a contract, not a model): Workspace holds a fixed bounded number of slots and a revision that advances by one per cycle. Pods submit Proposals (author pod and generation, content digest, PayloadRef, computed_against revision, requested Bid); neither Proposal nor WorkspaceConfig can carry or change a gate, level, threshold, report or verifier, and slot content is Authority::Provisional (invariant 4). Workspace::run_cycle takes a host CycleHost (verifier, VerifierIdentity recorded in the snapshot, AuthorRegistry) and is two-phase: the whole plan is computed without touching the workspace (a verifier panic is caught and judged Unknown with the hard finding verifier-panic, counted), then committed with no fallible step. Order: drop subscriptions of revoked Pod generations; retire incumbents (AuthorRevoked, Aged, Explicit, or Contradicted when Revalidation re-runs the verifier on the incumbent's original proposal and check_verification_gate no longer passes; SlotDecay::NeverUnsafe needs an acknowledgement and a revalidation); judge pending proposals (stale unless within max_staleness and no slot changed since, revoked author, then check_verification_gate = Candidate::passes of ptr-feedback, pinned against it in tests, score never read); admit gate-passers by effective bid (requested bid clamped by max_bid and the registry's per-author ceiling), seeded SHA-256 tie-break, proposal id, with duplicate content keeping its first author, a per-author slot cap and a per-author pending quota; opt-in Displacement::Policy (default off) lets a challenger that passed the gate at a level not below the incumbent's, beat its bid by a margin, after the incumbent's min residency, take an unpinned incumbent's slot under per-cycle and per-author caps, recorded as RetireReason::Displaced. Every loser has a counted Refusal with its reason and findings. Finding messages are host-side by default (invariant 13): snapshots carry bounded finding codes and hard flags, messages go to CycleReport::host_findings unless FindingVisibility::Public; findings per snapshot are bounded. One immutable Arc<WorkspaceSnapshot> with a SHA-256 digest is offered to every subscriber's bounded mailbox; a full mailbox refuses the new snapshot (counted) and never blocks
- StructuralOp::outcomes is the single post-operation state table for an admitted structural operation (ExpertOutcome, OutcomeKind): operands first, then results; results enter Serving at state_version 1, Merge and Split sources become Superseded, Freeze gives Frozen, unfreeze Serving, Prune and Retire Retired with their reason, and each operand's state_version advances by one; a reactivated Retired(GateFailed) source yields no operand outcome because its pod now names the new generation. The runtime registry and the ptr-state projection both apply it
- Decoding an evidence output no longer sizes an allocation from the dependency or provenance count stored in the record: the vectors grow with what is read, so a forged count ends at the first missing byte as an error instead of a capacity-overflow panic

## Mission

Defines specialist computational modules through semantic contracts rather than fragile tool names.

PTR keeps this responsibility in its own crate so the semantics remain stable even when an external library or implementation is replaced.

## Responsibilities

- Pod trait and manifests
- typed input/output contracts
- capability/effect declarations
- lease and lifecycle state
- local/process/remote/GPU Pod modes

## Explicit non-responsibilities

- global scheduling policy
- semantic authority
- model-specific prompting

## Data flow

| Direction | Contract |
|---|---|
| Input | Validated Pod request and typed input |
| Output | Typed result, observation, receipt or error |
| Failure | Explicit typed error / rejected state; no silent fallback that changes semantics |
| Observability | Standard PTR tracing fields and a stable component span |

## Technical approach

- Native Rust Pods
- process isolation
- Iroh remote transport
- DLPack/CUDA for tensor payloads
- ROCK-style environments for stateful action Pods

External projects are **candidates**, not architectural authority. The PTR-owned traits and domain types must remain usable with a replacement backend.

## Core invariants

1. Revoked leases cannot invoke.
2. Effects declared by the Pod are checked before execution.
3. Pod names are not the semantic contract.

These invariants should be executable wherever possible through unit, property, lifecycle or chaos tests.

## Failure model

The component must fail closed for semantic or effect-safety violations. Infrastructure failures should surface as typed errors that preserve request, revision, generation and provenance context. Retries must be idempotent whenever the operation may cross a process or network boundary.

## Performance model

Measure before optimizing. Benchmarks should record at least latency distribution, throughput, allocations/resident memory, queue depth or working-set size where relevant, and the cost of verification. Performance optimizations may not bypass generation, revision, capability or evidence checks.

## Security and privacy

- Treat external inputs and backend outputs as untrusted until validated.
- Do not put raw secrets/private evidence into generic tracing or inspection.
- Preserve provenance on every promotion from raw/possible evidence to stronger semantic state.
- External effects pass through `ptr-security` even if this component already performed local validation.

- [environment-runtime](../../evaluations/components/environment-runtime/README.md)

## Tests required before production use

- Contract/unit tests for all domain transitions.
- Invalid, stale-generation and stale-revision cases.
- Cancellation/retry behavior.
- Property tests for invariants where practical.
- Cross-backend equivalence if more than one backend exists.
- Observability and redaction checks.
