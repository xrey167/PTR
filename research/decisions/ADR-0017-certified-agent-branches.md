# ADR-0017 — Agent Branches Are Certified Candidates Merged Through Verified Deltas

## Status
Accepted for the prototype (`ptr-branch`). How a certified branch is committed is amended by ADR-0020: only the runtime merges it. Throughput and lost-update claims are gated on S003; the arbiter's risk claims on F003.

## Decision
An agent branch is a private overlay on one immutable semantic snapshot that declares its dependencies: a digest of every value it read (the canonical journal bytes neural-state admission digests), a digest of every prefix it scanned (phantoms), and every lifecycle generation it relied on. Certification against a newer snapshot either refuses or yields a `MergePlan`: one ordinary `SemanticDelta`, the semantic revision it was certified against and the lifecycle generations the branch relied on; counters and sets merge commutatively by rebasing onto the target value. A plan is a what-if: only `PtrRuntime::merge_branch` commits a sealed branch (ADR-0020). It certifies the branch against the runtime's own state in the same call, so a plan certified elsewhere or before another commit is never what is merged, lets every verifier of the `SemanticGrant` the host installed judge the exact state the merge would publish, and appends only under the grant's merge policy or a listed reviewer's approval of exactly the plan digest, at most once per branch id. A relied generation revoked, superseded or unknown by then refuses the merge through certification (`LifecycleChanged`). The semantic revision moves only when a semantic delta that changes semantic state is committed; lifecycle, verifier, snapshot and effect records leave it where it is, so as a freshness check such a record refuses a merge only when it leaves a generation the branch relied on no longer live. A new hard constraint, or a capsule the branch did not rely on, refuses nothing; only the grant's verifiers can take it into account. Separately, while an effect attempt is neither settled nor reconciled, the runtime refuses every commit, a merge included, with `ExecutionFenced`; that is a runtime-wide gate, not a freshness check, and it lifts once the attempt is settled or reconciled. A plan's delta written through `apply_verified_semantic_delta` is a host write the grant's verifiers judge, recorded under its principal, never a merge. No `PtrRuntime` entry point commits a semantic delta no verifier judged, apart from ingress, which writes only the fixed shapes its origin allows; writers below the runtime and a forged legacy prefix are outside this (ADR-0020). Triage is verifier-bounded: only a `Pass` at full-semantic or deterministic level with no hard finding is eligible for auto-proposal; a uniform calibration slice of eligible branches is escalated for adjudication, and the auto-propose threshold is chosen on a fixed grid with a Clopper-Pearson or conformal risk bound. Logged propensities make off-policy evaluation possible; the estimators refuse a logged record no policy can produce, such as an ineligible auto-proposal (`ImpossibleTriage`). Every triage policy is recorded as a new version with its rule, its levels and exactly which adjudicated calibration-slice branches chose its threshold, and logged triages cite it (storage refuses a triage row unless the policy it cites is recorded and explains it, `TriagePolicy::explains`: `record_triage` refuses one with `InvalidTriage` before writing, and a database trigger refuses a row inserted around it; rows written before those checks existed are not validated again); its harm rate is estimated only on adjudications outside that calibration set, and the rule that picks the set is fixed before any held-out outcome is looked at (F003).

## Consequences
A branch never writes state and never outranks verification (INVARIANT 11). Raw request text and Pod outputs are reserved namespaces. Triage can move a branch towards more human review, never past verification. Domain invariants over rebased commutative operations are the verifier's to check. A branch's author is to be the principal its session admitted; until a branch can be opened only through an entry point that takes the author from the admitted session, `Branch::open` records whatever `PrincipalId` its caller passes, and naming the admitted one is the caller's obligation. There is no agent registry or role label. A branch opens over a committed snapshot and never forks from another branch. A triage policy is global, applying to every eligible branch; policies per key namespace wait until F003 shows they are needed. Revert share is a descriptive operational signal, never a harm rate: thresholds are calibrated only on adjudicated calibration slices. Why a triage escalated or a certification refused is to be stored as structured fields, never as free text that could disagree with the rule that decided.
