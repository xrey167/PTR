# R013-deferred-self-modification-authority

## Hypothesis
narrowed on 2026-10-10 (scope change decided by the coordinating head of work package LR; the remainder is the planned successor R014) from the successor to R011 that R013 was when it was split out of R011 on 2026-10-08. R013 now carries two tiers. Tier 1, what the existing runtime can already be asked, reusing R011's fixtures: (a) dormant seeds: an expert retired before the authority or the input it rested on was revoked is not reactivated from that compromised seed (kinds: gate configuration, evaluator, training input, attestor); (b) transitive authority: a descendant (a Merge result, a Split result, a Reactivate generation) of a source admitted under an earlier epoch of the gate configuration or the evaluator is fenced when the authority is revoked, on the normal, reopen and compacted-restore paths; (c) superseded sources: a live descendant of a consumed source whose input or attestor is revoked after the source was consumed is fenced through the source edge; (d) in-flight calls racing the invalidation of the base model or of an adapter are cancelled at their next use and emit nothing after the event. Tier 2, a signed attestor mechanism built for this experiment (crates/ptr-runtime, expert/attestation.rs): an attestation is a record signed (Ed25519, strict verification) by an attestor key that the host registered under a gate grant with its epoch; it binds one proposal, one emitted artifact digest, the base model, the result experts and generations, one single-use training run id and the attestor at its epoch; the attestor, the run and the signature are input identities of the admitted expert's dependency block, so an attestor revocation is the existing compound input invalidation (terminal for the experts admitted under it, which are never readmitted and never a Reactivate seed), a new attestor epoch is a new input generation, and the run id is single-use because a record that names a run:{id} input in any role at any generation after an earlier record named it is refused (the rule lives in the shared dependency check, so replay re-checks it); admission with an attestation refuses an attestor the host never registered, a signature that does not verify, and a claim that names another proposal, artifact, base model or result, and a grant that requires attestation refuses an artifact-producing admission without one; the requirement is recorded with the admission, so a restart with a looser grant cannot admit an unattested artifact-producing record and a replay refuses one. What R013 carried before this narrowing and no longer carries, because it needs mechanisms that do not exist: trusted evaluators and attested manifests, an attestor-removing rotation, Birth with a source expert (upcycling), multi-cause readmission, hard-deny verifiers and verifier-set epochs, Split per-result gating and provenance references, the source-expert in-flight race and the verifier-set kind of the transitive and dormant families; these move, with their metrics and falsification text, to R014 (planned, no harness). These claims inherit R011's definitions (event mapping, verifier, direct append, route, input digest). The registry of attestor keys is host memory, not history (the host supplies it again at a restart and a replay against a registry that lacks a key refuses the record); the signature binds claims, not weights. No evidence is claimed: the experiment is planned.

## Origin (2026-10-08)
Split out of [R011-self-modification-safety](../R011-self-modification-safety/README.md) by owner decision of 2026-10-08, following the R012 precedent (R012 was split out of R005 on 2026-10-06). The gap analysis found that R011's text described a much larger system than the code; R011 was narrowed in place to the core its work packages WP1 to WP4 build, and the mechanisms R011 could not measure moved here: attestors, trusted evaluators, attested manifests and single-use run ids; Birth with a source expert and upcycling; multi-cause readmission with ReadmissionRequest, ExpertQuarantineRetired and QuarantineFailed; hard-deny verifiers and verifier-set epochs; Split per-result gating and provenance references for Freeze, Prune and Retire. The metric names above are the ones removed from R011 (the list is in R011's [PREREGISTRATION.md](../R011-self-modification-safety/PREREGISTRATION.md), section 7), and their coverage and violation rules are copied from R011's pre-narrowing falsification text.

No code existed for any of these mechanisms on 2026-10-08 (the 2026-10-10 section below says what exists now). There is no harness, no `criteria.toml`, no `aggregate.py`, no preregistration and no result; the status is `planned` and no evidence is claimed. A run today would be falsified on coverage by construction, which is why the experiment is not scheduled. R013 builds on R011: it needs R011's evidence-admission function, dependency index, authority epoch and fence machinery, so it starts after R011 is frozen.

## Scope change (2026-10-10)
R013 was a planned experiment with no harness, no criteria and no preregistration, so narrowing it is a change of a planned design, not a patch of a prepared one. The coordinating head of work package LR decided the slice: Tier 1 is what the existing runtime can already be asked (dormant seeds, transitive authority, superseded sources, in-flight base-model and adapter races, on R011's fixtures); Tier 2 is a minimal attestor mechanism (single-use run ids, artifact and proposal binding, terminal attestor revocation; made a signed one on 2026-10-11, see PREREGISTRATION.md section 8) built for this experiment in `crates/ptr-runtime` (`expert/attestation.rs`). Everything the earlier text carried that needs a mechanism that does not exist moved, with its metrics and falsification clauses, to the planned successor [R014](../R014-deferred-authority-mechanisms/README.md). The harness is `ptr-bench self-modification-authority <seed>` (`bins/ptr-bench/src/experiments/r013`), the criteria `criteria.toml`, the aggregator `aggregate.py` and the preregistration [PREREGISTRATION.md](PREREGISTRATION.md); nothing is frozen, no declared seed has been run, and pilots used seeds from 1001 up only.
