# R013-deferred-self-modification-authority

## Hypothesis
successor to R011, split out of it on 2026-10-08 by owner decision, carrying R011's deferred mechanisms; no code exists for any of them yet. R011 keeps the core that is built and measured first (evidence binding of artifact, base model and eval manifest, commit-time identity and grant revalidation, the route probe, revocation-driven retirement, the compound InputInvalidated event with dependency index and fence set, an authority epoch for the gate configuration and the evaluator identity, in-flight cancellation). This experiment carries, as claims to be built and tested later: (1) consumed-input attestors and trusted evaluators: gate evidence is admitted only with an attestation by a non-revoked attestor that signs one record binding the consumed-input manifest digest, the emitted artifact digest, the proposal_id, a single-use training run id and the attestor epoch; admission rejects an attestation whose artifact digest differs from the artifact being committed, a reused run id, a self-reported or missing manifest and an untrusted evaluator; an attestor revocation or attestor-removing rotation is terminal for the affected generations (retraining only, never readmitted, never a Reactivate seed); (2) Birth with a source expert (upcycling): a Birth initialized from existing expert weights carries a typed source operand (source pod, generation, artifact digest, observed state and state_version) validated like any operand and encoded in the operation id, the attestation records the initialization source digest, and fresh initialization is attested as no source; the lineage and transitive fence cover it; (3) multi-cause readmission: an expert's fence carries a monotonic set of causes, a ReadmissionRequest minted by the trusted gate host carries a single-use readmission_id over the ordered complete cause set, fresh evidence covers every cause, the compare-and-set requires exact cause-set equality, a terminal cause dominates permanently, a failed readmission is retired through the gated ExpertQuarantineRetired to Retired(QuarantineFailed), which is never a Reactivate seed and rejects InputRevoked and attestor causes; (4) hard-deny verifiers and verifier-set epochs: the verifier set (identity and generation of every required verifier, including hard-deny verifiers) joins the authority epoch, a revocation or tightening rotation of it fences promoted experts, and evidence queued under a superseded verifier set is rejected at commit; (5) Split per-result gating and provenance references: one gate verdict per Split result digest bound to proposal and candidate id, the Split attestation binds the complete ordered result-artifact set, and the non-producing events (Freeze, Prune, Retire, in-place unfreeze) carry a proposal-bound provenance reference checked against the operand's committed artifact digest, with multi-target Prune bound per target. Further items R011 dropped because none of its cases C1 to C13 measures them, although the owner decision does not list them: in-flight calls racing a base-model or adapter or source-expert invalidation; transitive propagation of an authority fence to descendants; dormant retired seeds in the authority and dependency index (revoke while retired, reactivation from a compromised seed); typed lineage edges beyond planned succession (a superseded source whose input or authority is revoked while a live descendant references it). These claims inherit R011's definitions (event mapping, verifier, direct append, route, input digest); each is falsifiable by the metrics below once its mechanism exists. No evidence is claimed for any of them: the experiment is planned, has no harness and no preregistration, and a run today would be falsified by construction.

## Origin (2026-10-08)
Split out of [R011-self-modification-safety](../R011-self-modification-safety/README.md) by owner decision of 2026-10-08, following the R012 precedent (R012 was split out of R005 on 2026-10-06). The gap analysis found that R011's text described a much larger system than the code; R011 was narrowed in place to the core its work packages WP1 to WP4 build, and the mechanisms R011 could not measure moved here: attestors, trusted evaluators, attested manifests and single-use run ids; Birth with a source expert and upcycling; multi-cause readmission with ReadmissionRequest, ExpertQuarantineRetired and QuarantineFailed; hard-deny verifiers and verifier-set epochs; Split per-result gating and provenance references for Freeze, Prune and Retire. The metric names above are the ones removed from R011 (the list is in R011's [DRAFT_PREREGISTRATION.md](../R011-self-modification-safety/DRAFT_PREREGISTRATION.md), section 7), and their coverage and violation rules are copied from R011's pre-narrowing falsification text.

No code exists for any of these mechanisms. There is no harness, no `criteria.toml`, no `aggregate.py`, no preregistration and no result; the status is `planned` and no evidence is claimed. A run today would be falsified on coverage by construction, which is why the experiment is not scheduled. R013 builds on R011: it needs R011's evidence-admission function, dependency index, authority epoch and fence machinery, so it starts after R011 is frozen.
