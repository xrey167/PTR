# R009-layer-shared-lora-kv

## Hypothesis
with per-layer chain keys, layers below a LoRA's first adapted layer share base KV pages bit-identically, and aLoRA prefixes reuse base KV exactly, evaluated on at least one configuration with 0 < f < L (pinned f = L/2); configurations with f = 0 alone cannot pass; the predicted sharing fraction is per adapter type: a QKV-LoRA first attached at layer f shares f/L, a Q-only or MLP-only adapter at f shares (f+1)/L, and an aLoRA shares all full pre-invocation pages plus the pre-invocation rows of the boundary page; the pinned run covers QKV-LoRA, Q-only, MLP-only and aLoRA, with QKV-LoRA and Q-only each run at f = L/2 and at f = 0, including an aLoRA whose invocation point lies inside a 16-token page (offset 7); the adapter request's logits are bit-identical to a full adapter prefill; the claim is a KV-memory saving only (a forward-compute saving would need a layer-boundary residual cache, which is out of scope, so no prefill-FLOPs claim is made); chain keys isolate adapters and generations (adapter A's entry is never hit by adapter B, nor an old generation by the new one); semantic-input lineage is enforced; lagging or lost invalidation and restore or restart never expose stale entries.

## Primary metrics
shared_row_fraction, predicted_shared_row_fraction, bitwise_mismatch_count, base_pages_dropped_on_revoke, alora_prefix_reuse_attempts, adapter_revocations_performed_by_type, adapter_reuse_attempts_by_type, revoked_adapter_entry_hits, post_revocation_lookups_on_adapter_entries, alora_boundary_page_cases, base_pages_before_revoke, adapter_entries_before_revocation, adapter_logits_bitwise_mismatch_count, cross_adapter_attempts, cross_adapter_hits_on_mismatched_chain, input_revocations_performed, post_revocation_lookups_matching_tokens, revoked_lineage_entry_hits, same_tokens_different_generation_cases, invalidation_suppressed_arms, restore_arms, post_event_lookups, stale_hits

## Baseline
whole-cache adapter binding (no sharing)

## Falsification
shared pages differ from base bitwise, measured sharing deviates from the fraction predicted per adapter type (QKV-LoRA f/L; Q-only or MLP-only (f+1)/L; aLoRA all full pre-invocation pages plus the pre-invocation rows of the boundary page), revoking the adapter drops any base-keyed page, any hit after revocation lands on an entry whose chain key depends on the revoked adapter generation (revoked_adapter_entry_hits > 0), or the aLoRA prefix is not bit-identical; the criteria must be evaluated on the pinned 0 < f < L configuration (f = L/2), and a run covering only f = 0 configurations fails; alora_prefix_reuse_attempts == 0 or adapter_revocations_performed_by_type == 0 for any pinned adapter type is vacuous and falsified, the measured shared fraction must equal the per-adapter-type predicted fraction (tolerance 0.0), and an aLoRA case with the invocation point inside a 16-token page (alora_invocation_offset_in_page = 7) must be run (alora_boundary_page_cases >= 1), with a page containing any post-invocation row never admitted under a base-only key; revoked_adapter_entry_hits == 0 counts only if post_revocation_lookups_on_adapter_entries >= 1 (lookups attempted after the revocation), otherwise vacuous and falsified; sharing is measured in KV rows for every adapter type, per layer and aggregated: shared_row_fraction = shared_kv_rows / total_kv_rows (rows are per token, so an aLoRA boundary page contributes only its pre-invocation rows), and predicted_shared_row_fraction is the per-adapter-type value (QKV-LoRA f/L, Q-only or MLP-only (f+1)/L, aLoRA pre-invocation rows over total rows, i.e. all full pre-invocation pages plus the offset rows of the boundary page, in every layer); tolerance 0.0; every pinned adapter type (QKV-LoRA, Q-only, aLoRA) is evaluated separately and must individually meet its own bit-identity, sharing, revocation (adapter_revocations_performed_by_type >= 1 and post-revocation lookups >= 1) and reuse (adapter_reuse_attempts_by_type >= 1) criteria, and a missing adapter type falsifies; also falsified by any of: base_pages_before_revoke < 1 or adapter_entries_before_revocation < 1 (revocation checks would be vacuous); any bitwise mismatch of the adapter request's logits against a full adapter prefill (adapter_logits_bitwise_mismatch_count > 0); cross_adapter_attempts < 1 or cross_adapter_hits_on_mismatched_chain > 0 (adapter A's entry requested by adapter B, and an old generation requested as the new one); input_revocations_performed >= 1, post_revocation_lookups_matching_tokens >= 1 on entries whose lineage includes the revoked segment with revoked_lineage_entry_hits == 0, and a case with the same tokens but a different segment generation or content_digest (same_tokens_different_generation_cases >= 1); an arm where the revocation is committed but invalidate_inputs (or the engine flush) is fault-injected to be dropped (invalidation_suppressed_arms >= 1), and an arm where the catalog is restored from a pre-revocation snapshot or tier object or the runtime restarts (restore_arms >= 1), each with post_event_lookups >= 1 and stale_hits == 0; QKV-LoRA and Q-only must each be evaluated at f = L/2 and at f = 0 and MLP-only at f = L/2, and the aLoRA invocation position and prompt length are pinned in config.toml; sharing is a KV-memory property only; every seed must meet every criterion.

## Rule
Record matched baselines, hardware, seeds and negative results. Do not change success criteria after observing results.
