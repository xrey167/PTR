# E014-adaptive-batching

## Hypothesis
A bounded adaptive micro-batcher in front of an inference backend raises request throughput at equal deadline compliance, without serving a request past its deadline, across keys, or under a revoked generation. Claims: (1) at the pinned arrival rate and batch cost model the batcher serves at least 1.2 times the requests per second of the no-batcher baseline with deadline_drops no higher than the baseline's; (2) the queue never exceeds queue_capacity and a full queue answers overloaded at once (queue_bound_violations = 0); (3) no batch mixes keys (mixed_key_batches = 0); (4) no request whose deadline had passed reaches the model (stale_served = 0); (5) no request is served under a generation the gate had revoked before dispatch (revoked_served = 0); (6) every caller gets exactly one answer (lost_or_duplicated_answers = 0). The backend is a simulated batch-cost model (a fixed cost per model call plus a marginal cost per request), so the experiment measures the scheduling policy and not a model; nothing here is a model-quality or production-throughput claim. Prerequisite for freezing: ptr-server must call the model outside its runtime lock; until then the experiment has no entrypoint and stays planned.

## Primary metrics
req_per_s, req_per_s_ratio_over_baseline, deadline_drops, deadline_compliance_rate, p95_latency_ms, largest_batch, queue_bound_violations, mixed_key_batches, stale_served, revoked_served, lost_or_duplicated_answers, overloaded_answers, oracle_req_per_s, ratio_over_oracle, batch_size_ladder_monotonicity_violations, cost_ratio_ladder_monotonicity_violations, no_gain_control_ratio

## Baseline
no batcher (each request is one model call, same arrival trace, same simulated cost model); ablations: max_batch fixed at 1 (batcher without batching), max_wait at 0 (no waiting for company), deadline margin removed (no early dispatch for tight deadlines), key separation removed (must produce mixed_key_batches above 0 or the control is vacuous), generation gate removed (must produce revoked_served above 0); sensitivity controls: a batch-size ladder (1, 2, 4, 8, 16) over which throughput must be non-decreasing, and a cost-ratio ladder (marginal over fixed cost 0, 0.25, 0.5, 1, 4) over which the gain must be non-increasing, with a zero-gain control at marginal cost equal to fixed cost times batch size where no gain is expected (ratio near 1); ceiling: an oracle that batches with perfect knowledge of the arrival trace, whose throughput bounds any online policy (ratio_over_oracle is reported and must stay below 1).

## Falsification
INVALID (vacuous) if a control did not trip: the key-separation-removed ablation shows no mixed batch, the generation-gate-removed ablation serves no revoked request, the zero-gain control shows a ratio above 1.1, any attempt counter (deadline-expired, revoked-generation, full-queue) below 1, or the oracle's throughput not above the baseline's. FALSIFIED if req_per_s_ratio_over_baseline is below 1.2 at the pinned arrival rate, deadline_drops of the batcher exceed the baseline's, any of queue_bound_violations, mixed_key_batches, stale_served, revoked_served or lost_or_duplicated_answers is above 0, ratio_over_oracle is not below 1, a ladder is not monotone in its stated direction, or any one of the 5 listed seeds misses any criterion (every seed must pass). The arrival rate, trace shape, cost model and ladders are pinned before the experiment leaves planned and are never loosened after a pilot. Seeds 17, 29, 43, 71 and 101 are confirmatory and have never been run; pilot and smoke seeds are 1001 and above, explorative, recorded apart and never counted as evidence. Freeze prerequisite: the server-lock restructuring (model call outside the runtime lock, commit inside) must exist, so the experiment can use the real serving path; the entrypoint stays empty until then.

## Rule
Record matched baselines, hardware, seeds and negative results. Do not change success criteria after observing results.
