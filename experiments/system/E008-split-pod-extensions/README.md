# E008-split-pod-extensions

## Hypothesis
E008 is the successor of E007 (the CPU core of the pipeline split) and holds what E007 leaves out, in three parts that are registered together and may be built, frozen and run separately. Part A, CPU, no network (the extension kinds moved out of E007 by the owner decision of 2026-10-09): (A1) the signed ActivationFrame carries input_lineage, the identity, generation and digest of every semantic, memory and derived input that contributed to the activation, and the ordered (Raw, content_digest) ancestry of every Raw segment that influenced it; the downstream cache key includes the activation-frame digest and the ordered raw ancestry, and downstream use-time admission revalidates the lineage against live generations, so a dropped Revoke or index lag never serves KV derived from an invalidated input, and an earlier Raw segment removed or changed with the typed inputs, chain and positions equal is never reused (reuse_after_raw_ancestor_removed = 0); (A2) upstream_chain carries every effective upstream model-side dependency of the closed list (base model, every adapter and every expert of the upstream layer range, each with identity, generation and digest, and a fence epoch for experts) and downstream admission revalidates all of them: an expert fenced, an adapter revoked or superseded while a frame is buffered or in flight, and the upstream base model revoked or superseded never let a downstream pod reuse KV derived through them; (A3) the signed frame carries mode (KvReuseMode) and taint (KvReuseTaint), the downstream cache key and dependency set include them, an Approximate frame can never populate or hit the Exact downstream namespace, and any output derived from it carries the taint to the effect boundary; (A4) downstream caches of split frames are never persisted: an attempt to snapshot or tier a downstream entry is rejected, no restore exists, and a restart drops them; (A5) the full invalidation coverage matrix of the closed dependency-kind list: dependency kind (upstream stage generation, semantic input, memory input, derived input, upstream-chain expert, upstream adapter, upstream base model) x invalidation type (revocation, supersession and, for the expert, fence) x path (normal, lag with the Revoke message dropped or delayed, in flight), 45 cells, each at least 1 and a stale hit or escaped output in any cell falsifies; the restore path does not apply because no KV is restored on a Pod; every element of upstream_chain and of input_lineage has exactly one matrix kind and vice versa, enforced by a checker. Part B, CPU and loopback network (the transport E007 does not use): the chunked frames of E007, including the 16 MiB frame as five chunks of at most 3.5 MiB, travel between two PodHost and PodClient endpoints over loopback iroh (ptr-net, podwire-backend), one chunk per request, and arrive bit-identically with every typed rejection of E007 unchanged; the receiver admits only the allowlisted schemas on the real endpoint, a replay after a reconnect is refused with FrameReplayed, and the chunk MAC or signature is bound to the connection's authenticated principal rather than to a key the test registers. Part C, needs a GPU or a real model (not buildable on the CPU container): (C1) a real checkpoint split at an internal layer across two device contexts on the candle-cuda path, compared with the single-device run of the same checkpoint on the same device: bit-identical logits and per-layer KV bytes when both stages run on the same device with batch-invariant kernels, and otherwise a maximum absolute logit difference and a top-1 agreement bound that are derived a priori from the F32 accumulation-order model and pinned before the first run; (C2) the boundary dtypes F16 and BF16 with a defined cast, compared with the F32 boundary on the same checkpoint (agreement and error bounds pinned a priori); (C3) the measured activation bytes per token crossing the boundary against the KV bytes the downstream pod keeps, so that the claim that only activations cross Pods is a measured byte ratio for a real model width and not an assertion; (C4) end-to-end latency of the split against the single pod on the same hardware, reported and never gated. Nothing in Parts A and B claims anything about a production model, and nothing in Part C is claimed until it has run on the declared hardware profile.

## Baseline
the single-pod run (bit-identity), a downstream cache keyed by frame digest that trusts the Revoke message (stale serves must occur), a cache without lineage or raw ancestry in its key (reuse after a removed Raw segment must occur), a cache with one namespace for both production modes (an Approximate frame must be served to an Exact lookup), and for Part C the F32 boundary on the same device

## Falsification
Each part is invalid (vacuous) and counts as falsified if any coverage prerequisite of that part is unmet: every attempt and case counter of the metrics list at least 1, for every cell of the invalidation coverage matrix separately (45 cells, never as an aggregate), for each control baseline (it must produce the stale serve, the reuse after removal or the cross-namespace hit it exists to show), and for Part C that the declared hardware profile and the checkpoint pin (repository and revision of the weights and of the tokenizer) are the recorded ones. Falsified if any of: reuse_after_raw_ancestor_removed, stale_input_lineage_kv_served, downstream_kv_reuse_after_upstream_fence, downstream_kv_reuse_after_upstream_adapter_invalidation, downstream_kv_reuse_after_upstream_base_model_invalidation, approximate_frames_served_to_exact, untainted_outputs_from_approximate_frames, downstream_restore_attempts_admitted, outputs_after_upstream_invalidation, invalidation_matrix_stale_hits in any cell, matrix_frame_bijection_violations, loopback_bitwise_mismatch_count, loopback_non_allowlisted_admitted, loopback_replays_admitted, loopback_unauthenticated_principal_admitted or real_model_same_device_bitwise_mismatch_count is above 0; downstream_entries_after_restart is above 0; real_model_max_abs_logit_difference, boundary_dtype_max_abs_logit_difference or real_model_top1_disagreements exceeds the bound pinned a priori from the accumulation-order model before the first run (never from a pilot number); any one of the 5 listed seeds misses any criterion (every seed must pass). Latency and byte ratios are reported and never gated. The extension kinds of E007's original design that E008 takes over (input lineage, raw ancestry, mode and taint, persistence rejection, the expert, adapter, base-model, semantic, memory and derived matrix kinds) are specified in docs/architecture/36-kv-reuse.md section D and the E007 row of its invalidation coverage matrix; E008's preregistration pins the exact thresholds before it leaves planned.

## Rule
Record matched baselines, hardware, seeds and negative results. Do not change success criteria after observing results.

## Harness
Part A has a CPU harness in `bins/ptr-bench/src/experiments/e008/part_a/`. One seed is one run and prints exactly one JSON object on stdout:

```
cargo run -p ptr-bench --locked --release -- split-pod-extensions <seed>
```

`split-pod-extensions <cases> <seed>` is the form the mutation checker uses: `<cases>` scales the three seeded case families (raw ancestry, modes, persistence) and the record then says `"scale":"custom"` and is no evidence; the 45 matrix cells and the three controls always run in full. Exit status: 0 when every rule holds, 1 for a tripped falsifier (a product finding), 2 for a harness failure: a validity violation, an unmet coverage prerequisite, a metric gap, a case that cannot run or a control that does not trip. Seeds not listed in `experiment.toml` print a dry-run note on stderr.

The harness prints every Part A metric of this manifest (`reuse_after_raw_ancestor_removed` through `outputs_after_upstream_invalidation`, with `invalidation_matrix_cases` and `invalidation_matrix_stale_hits` per cell as `<kind>_<path>_<type>`), `control_trips` per control, a top-level mirror `stale_hits_in_<cell>` of every cell for the mutation checker, and its own reading of the coverage, falsifier and validity rules. E008 is `planned`: those lists are for the head to pin in the preregistration, and no part of this harness is frozen. Parts B and C are other harnesses.

The three controls are external baselines (small caches written for the harness), not the product with one mechanism removed: a control that trips shows the probe can see the failure it names. `matrix_frame_bijection_violations` is mainly a coverage check (the slot/kind mapping is a bijection and every kind is reached by a frame the harness builds), not a falsifier of a stale or tainted serve.

### Notes for the mutation plan (draft, not part of any freeze)
The harness prints `procedure.scale` and `procedure.seed_is_declared` but does not judge them: a custom-scale run or an undeclared seed can exit 0. As in E007 (`aggregate.py`), the E008 aggregate must refuse such a record as invalid (Codex P1 on PR #167, assigned to the aggregate of the registration package).

Part B's `REJECTION_KINDS` does not list the assembler's `deadline_too_far` and `frame_too_large`, so a regression of either over the socket is not a coverage failure; the preregistration adds both kinds with a network case each (Codex P2 on PR #167).

Every matrix frame carries the current digests and the invalidation also ends the generation's validity, so validity refuses before a digest comparison decides: removing `InputDigestMismatch` or the upstream manifest-digest check alone would keep all 45 cells green. The preregistration needs a digest-only sensitivity case (a live generation whose authoritative digest changed, or a forged frame digest) before those two mutations can be killed (Codex P2 on PR #167).

The fence epoch of an expert is the runtime's own (`RuntimeStageLiveness::fence_epoch`, the expert registry's committed state version), and the harness fences and readmits its experts through the real authority path.

`prefix_key_v2` repeats the mode, the taint, the Raw ancestry and the typed lineage on purpose, but the frame digest it also hashes already covers all of them. Removing one of those explicit terms alone changes no key, so it is an **equivalent mutant** and cannot be killed; planting it needs the digest's coverage removed too (an `also` edit). The killable mutations are in the digest, the admission and the use paths:
- skip `write_lineage` or `write_mode_taint` in `ActivationFrameV2::to_bytes` (the digest stops covering them; the explicit key terms then still hold, so pair it with the key term for the Raw cells);
- skip `revalidate_input` in `entry_fault`, or skip `entry_fault` in `live_entry` (lineage and chain revalidation at use);
- collapse `namespace_index` to one table, or `namespace_of` to Exact (single namespace);
- drop the cancel flag in `drop_entry` (an in-flight use survives the Revoke message);
- `finish_use` without revalidation (an output released after the invalidation);
- `finish_use` returning an Exact taint (taint dropped on release);
- `clear()` keeping entries (restart);
- `RuntimeStageLiveness::fence_epoch` answering the recorded epoch for any expert (the fence cells).
