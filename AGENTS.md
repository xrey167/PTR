# AGENTS.md

Binding working method for every agent that works in this repository (Codex, Claude Code, any other coding agent). `CLAUDE.md` is the Claude Code quick reference (commands, architecture, conventions) and does not repeat this file. If the two disagree, this file wins for method and `docs/INVARIANTS.md` wins for architecture.

Related documents: `docs/FREEZE_PROCEDURE.md` (full freeze procedure), `docs/LOCAL_START.md` (local machine setup), `docs/agents/KICKOFF.md` (kickoff prompt and goal), `docs/CLAUDE_TOOLING.md` (ptr-dev plugin and its agents).

## 1. Roles

**Head.** Plans, reviews, integrates, freezes and runs every Definition-of-Done check itself. The head is the only role that commits, merges, tags and signs. The head never trusts a hand-back: it re-runs the commands it relies on.

**Channel.** A coding package. One worktree per package, on its own branch. A channel never commits, pushes, merges, tags, signs or freezes. It edits only the files its package owns and does not touch files owned by parallel channels. It hands back exactly once, at the end (format in section 7).

**Reviewer.** Read-only. Reads the diff against the base, re-runs read-only and Python checks, and reports findings as P0, P1 or P2, each with `file:line`. The verdict is either "no open P0/P1" or a list of the open ones. Reviewers never edit.

Rules that apply to all roles:

- P0 and P1 findings are always fixed. A P2 finding is fixed or justified in writing.
- At most 4 coding channels run at once, plus read-only reviews.
- A lost or stalled channel is restarted from a handoff note (goal, owned files, state of the worktree, what was verified, what is open), not from memory.
- Permission laundering is forbidden: a channel that reports a refused stop or kill does not get the head to perform it on its behalf. The owner decides.
- Ask the owner only for irreversible steps or rule breaks. Everything else: decide conservatively and reversibly, and record the decision in a decisions log (suggested: a decisions file in the session scratch area, summarised into `evaluations/BATCH_DECISIONS.md` or `STATUS.md` when the decision changes the repository).

## 2. Repository rules

- Always pass `--locked` to cargo. For clippy use `cargo clippy --workspace --all-targets --locked -- -D warnings` (the `xclippy` alias cannot take `--locked`).
- Docs-as-code: a change under `crates/<crate>/src/**` or `crates/<crate>/Cargo.toml` also updates `crates/<crate>/component.toml`. Then run `python3 scripts/update_component_docs.py --write` (`make docs`) and verify with `--check` (`make docs-check`).
- Never edit vendored sources under `vendor/` (`docs/VENDOR_PATCH_POLICY.md`). The two records there change only as their checkers demand: `vendor/RETIREMENT.json` (for example naming a new workspace dependent of a patched crate in `blocked_by`, which `scripts/check_vendor_retirement.py` requires) and `vendor/CURRENT.json` (regenerated by `scripts/check_vendor_integrity.py` after a reviewed source change). Never force-push.
- Commits carry the attribution trailer the session prescribes. The format is `Co-Authored-By: <assistant name> <noreply@anthropic.com>`, followed by a `Claude-Session: <url>` line where the tool provides one. Pull request descriptions end with the line the tool prescribes. Do not invent names or URLs.
- The `model:` field of the plugin agents (`.claude/plugins/ptr-dev/agents/*.md`) names a model tier alias (for example `sonnet`) and is allowed; versioned model identifiers are not written into files.
- Never write tokens, DSNs or passwords into logs, files, commit messages or reports.
- Builds: only with at least 6 GB free disk. On small hosts use `CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 PYTHONDONTWRITEBYTECODE=1`. On the owner's GPU machines, two PCs with one card each (one RTX 3090, `hardware/rtx3090.toml`; one RTX 4090, `hardware/rtx4090.toml`; owner inventory of 2026-10-13, which replaces the earlier two-3090 desktop of `hardware/dual-rtx3090.toml`), more cargo jobs are fine (raise `CARGO_BUILD_JOBS` up to the core count); the other variables and the 6 GB disk floor stay. On those PCs run frozen confirmatory seed runs one at a time per PC: `scripts/run_experiment.py run` passes a restricted environment without `CUDA_VISIBLE_DEVICES`, so `CUDA_VISIBLE_DEVICES` alone does not reach a seed run. GPU pinning of frozen seed runs (OD-3, decided 2026-10-13, no runner change): a GPU experiment's manifest declares `PTR_CUDA_DEVICE` in `command_environment` before its freeze (the runner passes declared `PTR_*` variables through, `scripts/run_experiment.py`), its entrypoint wrapper sets `CUDA_VISIBLE_DEVICES=$PTR_CUDA_DEVICE` and prints the index into its result JSON (the run record names the declared variable, never its value), and the freeze script's `gpu` field exports both variables. An experiment frozen without that declaration runs on card 0, one at a time. On a single-card PC, pilots, smokes, tuning and mutation runs share that card with the seed runs and never run at the same time as one; on a machine with a second card, that card is for them; each is logged with its GPU index (`CUDA_VISIBLE_DEVICES`). Delete `target/` directories you created once you are done.
- Processes: kill only PIDs you started and verified yourself. Never `pkill`, never `pgrep -f`, never kill by name pattern.
- `.cargo/config.toml` never gets an `[env]` table.
- Generated files (component READMEs, `docs/components/STATUS.md`) are regenerated, never edited by hand.

## 3. Research rules

- `docs/INVARIANTS.md` is binding. Most often at stake: 4 (uncommitted state is never authoritative), 5 (search or index data never self-promotes to truth), 8 (queues are bounded), 11 (a learned score cannot override a deterministic verifier contradiction), 13 (secret redaction).
- Router, L3, self-model and experts never change gates, thresholds, verifiers or eligibility.
- Doc 38 indicators are functional only. `docs/MODEL_WELFARE.md` applies.
- Every claim is falsifiable: baseline, ablation and a sensitivity control, with no ceiling and no strawman baseline.
- Thresholds are never loosened after a pilot. Any loosening is disclosed. Chronology is disclosed.
- Tune only on pilot seeds >= 1001. Each confirmatory seed runs once.
- Exit codes: 1 is a product finding, 2 is a harness failure. A seed that exits with anything other than 0 or 1 stops the run.
- Decision order: validity (INVALID) before falsifier (FALSIFIED) before controls.
- COMPLETED only when the whole mutation check has `killed == total`.
- Negative results, product findings and the agent's own misdiagnoses are reported, not hidden.
- Prepared and frozen records are never patched. Create a successor with `scripts/new_experiment.py`.
- Every preregistered experiment must be listed in `LISTED_UNFROZEN` in `scripts/tests/test_research_gates.py`.

## 4. Freeze discipline

Summary only; the authoritative procedure is `docs/FREEZE_PROCEDURE.md`.

- `scripts/freeze/freeze_sign.py --dry-run` first.
- Before signing: gates pass, `EnrolledExperimentTests` pass, tree clean.
- `guard_on` / `guard_off` (`scripts/freeze/freeze_guard.sh`) around signing.
- Explicit paths only; never `git add -A` or `git add .`.
- Run the whole `mutation_check` on the committed frozen tree. Do not set `CARGO_TARGET_DIR` for it: `scripts/mutation_check.py` runs `ROOT/target/release/<package>`.
- Rerun the pilot and compare it field by field with the committed `pilots/pilot-<seed>.json`, excluding the declared timing keys.
- Seeds are read from the config, never retyped.
- Long runs: `setsid nohup`, with a timeout and a CPU-progress check. Running scripts are never edited.
- `STALE.toml` names the first provenance-changing commit.
- Tag names are not derivable from ids (for example `q003v3-prereg`). Pass them explicitly.

## 5. Merging

- Merge the integration branch into the experiment branches before a freeze.
- After every merge compare the rule digests of both parents (`scripts/freeze/digest_parents.py`) and run the gates.
- Typical append-at-end conflicts keep both sides: `experiments/preregistration.toml`, `experiments/registry.toml`, `LISTED_UNFROZEN`, the subcommand lists in `bins/ptr-bench/src/main.rs`.
- Generated READMEs and `docs/components/STATUS.md` are regenerated, never hand-merged.

## 6. Lessons of wave 13

- Local `stable` can be older than the MSRV (1.97 against 1.99). Run the `make ci-*` recipes with `+1.99.0`: `make -n <target> | sed 's/cargo +stable/cargo +1.99.0/' | bash -e`.
- Code changes under test of a completed experiment break its mutation anchors; `make python-test` catches it. Re-anchor the plan to the same defect, verify the kill without writing a record, and note it in that experiment's `STALE.toml`.
- `bindings/ptr-py` has its own `Cargo.lock`. Update it offline when workspace crate dependencies change.
- The ptr-cluster `cluster-backend` wire test asserts the compacted snapshot magic. Bump it together with the runtime format.
- The full `test_research_gates` takes 30+ minutes and `check_research_gates.py` about 20 minutes on 4 cores. Plan for it; do not kill it early.
- Q003's lexical half returns nothing on natural-language queries (`plainto_tsquery` ANDs all terms). Any hybrid claim needs a new preregistered experiment.

## 7. Report formats

**Channel hand-back (once, at the end):**

1. Changed files, one line each.
2. Commands run with their real output (copied, not paraphrased; secrets removed).
3. Open points and anything not verified, stated as such.
4. Decisions taken that the head should log.

**Head report:**

1. Results, each with its evidence class (measured and reproduced, measured once, derived, not verified).
2. Findings, including negative results and product findings.
3. Limits: what the evidence does not show.
4. Own errors: misdiagnoses and corrections made along the way.
